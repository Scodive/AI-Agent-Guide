## 3. 论文与技术候选分析

### 本周近期新增

**CMP — 记忆效用能否被识别（pure method，含理论分析）。** [原始记录](https://arxiv.org/abs/2610.02070)，Arman Behnam、Binghui Wang；v1 2026-10-01，无本次发现的后续修订。[全文](https://arxiv.org/html/2610.02070v1)给未检索记忆分配已知正概率曝光，用固定上下文槽位和自归一化逆概率加权识别条件效用。环境包括 LongMemEval、LoCoMo 和回放，区分曝光支持、识别指标与最终任务表现。学习价值是解释为什么只看已有检索日志不能判断所有记忆的价值。曝光池使用相关性标签，实用池选择未解决；单查询效用不直接决定未来留存。作者页关联[匿名代码](https://anonymous.4open.science/r/cmp-release-D0C3/)，内容未审计、未运行。入库是学习识别问题，不主张部署淘汰策略已验证。

**Incident-Arena — 修复运行服务如何验收（pure benchmark）。** [原始记录](https://arxiv.org/abs/2610.00648)，Andre Fu 等八位作者（完整名单见核验日志）；v1 2026-09-30，无本次发现的后续修订。[全文](https://arxiv.org/html/2610.00648v1)在临时 Kubernetes 环境部署真实开源应用并注入故障/负载，检查恢复、安全、重启和修改范围。20 任务、三个基底、10 个模型/Harness 配置，每推理档三次，总计 3000 试验；报告 Pass@1、成本和任务 bootstrap 区间。用它解释“能生成补丁”到“修复安全且持久”的距离。任务多数来自 Slack，模型与 Harness 混合，重复数小；主成功的功能验证与奖励投机的 LLM judge 后分析分开。摘要、汇总表和不同推理档的最佳数字口径不同，本周不引用一个统一排行榜百分比。完整方法代码未确认，CSV 代码留空。

### 较早遗漏补收

**MemGPT — 外部信息如何进入有限上下文（system/tool）。** [原始记录](https://arxiv.org/abs/2310.08560)，Charles Packer 等七位作者；首次 2023-10-12，本次读 v2 2024-02-12。[全文](https://arxiv.org/html/2310.08560v2)的分层存储、上下文队列、函数调用和控制流，为 A-MEM 的组织机制补前置知识。评估包括 MSC、50 个 NQ-Open 问题及嵌套键值检索，指标含正确率、ROUGE-L、相似度与 LLM 判分。作者报告的比较包含不同信息呈现方式，不能推成无成本无限记忆。作者[项目](https://research.memgpt.ai/)代码入口现重定向[Letta](https://github.com/letta-ai/letta)，论文版本与当前实现须分开。

**LATS — 如何把交互、反思与树搜索接起来（pure method）。** [原始记录](https://arxiv.org/abs/2310.04406)，Andy Zhou 等五位作者；首次 2023-10-06，本次读 v3 2024-06-06。[全文](https://arxiv.org/html/2310.04406v3)用选择/扩展/价值估计/回传及失败反思连接 ReAct 与 MCTS；检查 HotpotQA 100 问题、HumanEval/MBPP、WebShop、Game of 24。HotpotQA 有答案正确性 oracle；搜索后选一个答案的指标不等于只调用一次模型。环境状态回退与额外预算是可迁移性的限制。[作者代码](https://github.com/andyz245/LanguageAgentTreeSearch)入口已确认，不把仓库会议信息直接升级为正式来源核验。

**τ²-Bench — 用户也能行动时怎样评价协作（pure benchmark）。** [原始记录](https://arxiv.org/abs/2506.07982)，Victor Barres、Honghua Dong、Soham Ray、Xujie Si、Karthik Narasimhan；首次 2025-06-09，本次读 v1。[全文](https://arxiv.org/html/2506.07982v1)让 Agent 与模拟用户共同改变共享世界，用 No-User、Oracle Plan 区分推理和通信。retail 115、airline 50、telecom 114 任务，四模型、四次运行；关注重复一致性的 pass^k 和通信错误。用户由 LLM 模拟、领域人工设计，专家/新手知识差距未显式建模。[作者代码](https://github.com/sierra-research/tau2-bench)由全文脚注确认。现有 τ^τ-Bench 测系统构建，两者不是同一编号的修订版。

### 旧条目、观察项与质量判断

- **DeepSeek-R1**：首次 2025-01-22，本次读 v2 2026-01-04。[原文](https://arxiv.org/html/2501.12948v2)区分 R1-Zero 纯 RL 和 R1 的冷启动/SFT/多阶段 RL。由自我演进归入规划与推理；这是更正讲解，不是本周新论文或新修订。参数训练背景保留，运行时 RSI 的推论删除。
- **RAC**：既有条目，不重复入库。[原文](https://arxiv.org/html/2610.00980v1)在三个研究宿主观察到运行时选择最高均分，加入契约和验证的组合后均分下降。单种子、25 个任务、预算上限匹配；组件联合加入无法分开归因。用作机制边界，不否定多 Agent 路线。
- **Agent Q**：用[原始记录](https://arxiv.org/abs/2408.07199)纠正 2024 年、准确标题及 off-policy DPO；未完成实验全文核验，不增加 CSV。
- **CPE**：用[机制章节](https://arxiv.org/html/2609.01222v1)解释消息角色/持久作用域升级；与公开配置暴露研究相邻，完整攻击和当前版本核验仍暂缓。其他九项观察候选和理由见候选表。

以下是编辑取舍评分，1–5 分，依次为洞见/完整性/数值实验证据；不是正式评审或复现等级：CMP **4/3/3**（识别视角清楚，实用池限制）；MemGPT **4/3/3**（机制可教，评估局部且混合判分）；LATS **4/4/3**（机制及多任务分析明确，oracle/成本限制）；Incident-Arena **4/3/N/A benchmark**（功能与安全验收有价值，覆盖/归因不足）；τ²-Bench **4/4/N/A benchmark**（双控及消融明确，模拟用户限制）。纯基准不按榜单分数给数值证据评分。R1 背景复核 **4/4/4**，RAC 边界复核 **3/3/2**。评分仅服务本次阅读选择，不添加 CSV 字段。

## 6. 新方法怎样改善现有讲解

1. **README 记忆章节、路线步骤 5：保存即长期学习的跳步 → MemGPT 的上下文搬移与 CMP 的曝光识别 → 读者能检查信息是否进入模型及是否可从日志估计价值 → 补充/边界 → 重写末段并新增分支 → 实用候选池与留存策略仍未解决。** 原始来源：[MemGPT §2](https://arxiv.org/html/2310.08560v2)、[CMP 方法/附录](https://arxiv.org/html/2610.02070v1)。
2. **README 规划章节、ReAct 到 SWE-Search：缺反馈/状态连接 → LATS 将交互反思接到 MCTS → 读者比较搜索对象、反馈与预算 → 补充 → 新增桥段和路线 → oracle 与可回退假设不直接迁移到不可逆行动。** [来源](https://arxiv.org/html/2310.04406v3)。
3. **代码章节、Harness 验收：只列产品和修复分数 → Incident 的负载/重启/安全门 → 学会区分产物与持久结果 → 补充/边界 → 改为交付检查点并新增验收接口 → 20 任务且配置混杂，不能代表全部生产环境。** [来源](https://arxiv.org/html/2610.00648v1)。
4. **评估章节：用户被视为单纯给请求 → τ² 双控状态与 No-User/Oracle Plan → 可把通信、推理和可靠性分开 → 补充 → 新增协议段、路线并区别 τ^τ → 模拟用户代表性有限。** [来源](https://arxiv.org/html/2506.07982v1)。
5. **RSI 与 R1 两处：纯 RL、参数训练、程序自改混称 → R1 训练阶段区分及已有 GEPA/DGM 修改对象 → 避免凭反思或参数更新认定递归程序改进 → 更正/边界 → 重写分类、改 CSV 主题和专题连接 → 其他 RSI 论文仍沿用原核验，本周不是全面重新评审。** [来源](https://arxiv.org/html/2501.12948v2)。
6. **MAS 开头：角色协作必然超越单 Agent → RAC 小样本联合机制降分 → 学会先查预算、宿主、交接和验证效应 → 反例/边界 → 保留固定角色经典并新增运行选择 → 单种子与联合消融不支持因果分解。** [来源](https://arxiv.org/html/2610.00980v1)。
7. **MCP/框架推荐与 Harness 安全：接口自动隔离、旧工具首选 → MCP 官方安全实践、AutoGen 维护说明与 CPE 的角色/范围机制 → 理解授权责任和资料时效 → 更正/补充 → 两语言三层权限说明、维护状态及信任接口 → 不断言所有当前产品存在 CPE；Codex 资料未刷新。** [MCP 官方](https://modelcontextprotocol.io/docs/2025-11-25/tutorials/security/security_best_practices)、[AutoGen 官方](https://github.com/microsoft/autogen)、[CPE](https://arxiv.org/html/2609.01222v1)。
