# 每周研究与指南审查报告模板

每周在 `data/weekly-reviews/YYYY-MM-DD.md` 保存一份填写完整的报告。下面的要求用于组织真实分析；没有完成的核验写明“未完成”及原因，不以占位文字代替结论。公开报告使用仓库相对路径，不写个人机器路径或凭据。

## 1. 本周判断与优先事项

说明指南目前最需要改善的 1–3 个学习问题、证据依据和优先级。给出本周新增/修订/暂缓数量、是否存在影响准确性的错误，以及本次是否建议提交。把“已修改”“建议但尚未修改”“待核验”分开。

## 2. 基线与检索范围

记录日期、论文提交/修订时间窗口、仓库基准提交、上期报告及原有待审修改。写出实际检索渠道和关键词、候选与去重情况、实际阅读的全文和官方资料。说明漏检与不可访问的来源；有限检索不等于完整覆盖。

## 3. 论文与技术候选分析

逐项给出标题、首次提交与本次修订日期、原始论文/代码链接、论文类型、与现有内容的关系，以及收录/修订/暂缓理由。对入选候选写清研究问题、机制、实验环境和指标、支持的结论、局限与核验日期。较早补收工作明确标记，不称为本周新论文。

## 4. 整个项目的技术覆盖

对 SOP 中每一个方向填写：现有章节与代表阅读、覆盖判断、具体缺口或过时点、补充证据和建议动作。没有发现修改理由的方向也说明检查了什么及保留理由；无法完成核验的方向明确列出。对交叉主题解释它们如何连接已有路线。

## 5. 讲解结构与阅读路线

从读者的前置知识、术语、章节顺序、研究问题、机制解释、例子、实验和局限逐项检查。定位重复、跳步、概念混淆、只列论文而缺少解释的段落。分析中英文指南与专题是否一致、经典路线是否仍适合作为起点、近期方法应放在哪个学习阶段。

## 6. 新方法怎样改善现有讲解

对每项实际建议使用“原文位置及问题 → 新证据与机制 → 对学习的帮助 → 新旧关系 → 具体修订 → 尚存限制”的顺序。关系使用替代、补充、反例/边界或观察。必须说明为什么需要改、哪里值得保留，不能把宣传性结论直接替换原讲解。

## 7. 本次具体修改

逐文件列出修改位置、修改前的问题、做了什么、依据与验证结果；概念或路线变化附必要的修改前后片段。区分论文库新增、旧条目更正、导读重写、阅读顺序调整、链接/元数据修复和本周未改的建议。单独指出上期遗留修改，避免重复计为本周工作。

## 8. 检查、剩余问题与审核

记录 CSV/生成表格一致性、重复编号、来源与日期、代码归属、内部链接及网站来源路径的实际检查结果。列出本周无法核验的内容及下一步。记录当前文件差异和是否已暂存/提交/推送；周更交付时应是等待维护者审核的本地修改。独立网站同步与部署状态单独记录，不把本地检查通过写成上线成功。

最后提供简短审核摘要：本次推荐提交的改动、需要维护者判断的取舍、可直接查看的文件，以及本次是否已得到明确提交许可。
