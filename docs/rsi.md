# RSI：Agent 的递归自我改进

*Meta²增补与Terminal-RSI v3跟进核对：2026-11-10；其他条目沿用原日期。以下结论为作者报告，未独立复现。*

这里的 **RSI（recursive self-improvement）**限定为：系统提出对自身某个可复用组件的修改，通过可记录的评价反馈筛选修改，并让被接受的新版本参与下一轮改进。关键要问的是**改了什么、谁给分、改进能否迁移、下一轮是否真的使用了改进后的系统**。这比“Agent 反思了一次”或“模型训练后分数更高”更具体。

## 先用 Reflexion 理解反思记忆

经典 [Reflexion](https://arxiv.org/abs/2303.11366)分成执行、评价和反思：把环境/任务反馈转为语言教训，放入有界记忆，再重置任务重试。下一轮读到的内容改变了，模型权重和反思规则本身保持固定。因此它是 GEPA 之前的前置阅读：先问改了经验内容还是可复用提示规则，再问被接受版本是否继续生成下一代。仅有多轮反思不能证明改进器递归增强。

论文 v4 的 ALFWorld 最多 12 次试验累计成功，不是单次成功；代码任务隐藏测试的 pass@1 也可能先经过多次内部生成/自测。HotpotQA 部分条件有正确性反馈或给定证据，生成测试有假阳性，MBPP Python 还出现下降。用它学习反馈如何进入记忆，保留每轮结果、全部重试与失败，避免从“记下教训”跳到“持续自我升级”。[论文库记录](papers.md#paper-2303.11366)。

## 改进对象不同，证据也不同

| 层次 | 代表工作 | 改进对象与循环 | 不能据此推出什么 |
| --- | --- | --- | --- |
| 提示词/模块说明 | [GEPA](https://arxiv.org/abs/2507.19457) | 读取轨迹与工具结果，生成自然语言反思，更新提示词，并从候选的 Pareto 前沿保留互补经验。 | 改进提示词不等于修改模型权重，也不自动证明 Agent 能自主设计下一代模型。 |
| Agent 逻辑 | [Gödel Agent](https://arxiv.org/abs/2410.04444) | 用高层目标引导 Agent 改写自身逻辑和行为，再在推理与复杂任务上评估。 | 有限任务上的迭代收益不代表开放环境中无限改进。 |
| Agent 程序代码 | [Darwin Gödel Machine](https://arxiv.org/abs/2505.22954) | 从已有 Agent 档案采样，修改自身代码，用 Coding 基准筛选新版本；被保留版本可继续产生后代。 | 改进的是以固定基础模型为核心的 Agent 程序，不是基础模型自行重训。 |
| 科研 Agent 自身 | [Recursive self-improvement of AI research agents（AIDE²）](https://arxiv.org/abs/2609.26457) | 研究 Agent 改写自身代码，用 AI 研发任务筛选，并检查留出任务上的转移。 | 论文报告的是特定 Agent、任务和一次八天运行；不能概括为通用自主 AI 研发已解决。 |
| 改进器自己的 Harness | [VERSE](https://arxiv.org/abs/2610.02616) | 内层改执行器的 Harness，外层改优化器的提示、技能、工具与钩子；接受后的优化器版本用于后续轮次，模型权重与评估接口固定。 | 改进器参与下一轮不保证额外收益；自演化相对不自演化的 VERSE 并非每个测试配置都更好。 |

**相邻但不同：**[AlphaEvolve](https://arxiv.org/abs/2506.13131)用代码生成、自动评估与演化搜索改进**目标算法**，包括部分 AI 计算基础设施；这证明闭环算法发现有用，但算法改进不必然是 Agent 改写自己的改进器。[Voyager](https://arxiv.org/abs/2305.16291)积累技能库，适合作为持续学习的前置阅读。[DeepSeek-R1](https://arxiv.org/abs/2501.12948)讨论模型强化学习，不能直接当成 Agent 运行时 RSI 的证据。

## 可复用指导与任务内编辑

读完GEPA和VERSE，再用[Meta²](https://arxiv.org/abs/2611.05139)标出三个生命周期：离线优化并保留的Meta-Skill、仅本次运行有效的Harness补丁、随本次运行结束丢弃的检查点对话。模型权重和演化器接口固定；离线用训练反馈更新指导，部署时既不回写指导，也不把本次补丁带给下一任务。因此它是运行时适应与知识复用的补充，不据名称认定部署中的改进器发生递归继承。

训练中的特权verifier可用于产生对比，作者说对泄漏轨迹做过滤；部署时不可见留出verifier结果。这个边界要与结果取证分开：可读的工作区证据不是隐藏评分。所测跨任务携带补丁会退步，说明“接受本次编辑”和“允许跨任务保留”应分别评价；它没有否定GEPA/DGM/VERSE的持久演化路线。五次/三次重复的是测试执行，文中未报告指导构建的独立重复；各骨干分别构建指导。完整范围见[论文库](papers.md#paper-2611.05139)。

## 持久修改的回归检查

[Self-Healing Harness](https://arxiv.org/abs/2609.24130)补充“谁决定修改能否保留”：Agent 提议行为规则，外部门控检查触发失败是否改善、旧案例是否退化，再决定跨任务保留。它改的是运行指令和规则，基础模型权重固定，适合作为 RSI 的监督机制阅读。

证据边界包括：单种子连续适应，没有独立学习/测试划分；16 个配对中只有 2 个任务得分差异区间排除零；Terminal-Bench 使用缺少保护案例测试的后续试验。因此应关注回归机制及其失效边界，不能把它概括为通用自我改进已得到验证。

## 读 RSI 论文时检查五个问题

1. **修改面**：提示词、工具、记忆、搜索策略、评估器、完整 Agent 代码，还是模型参数？
2. **反馈面**：训练任务与保留任务是否隔离？运行失败、超时和验证错误怎样处理？
3. **递归性**：新版本是否真的成为下一轮的修改者，还是仅对同一固定系统做多次搜索？
4. **收益**：报告的是任务成功率、成本/时延、迁移能力，还是只看优化器反复使用的同一评分？
5. **边界**：改进是否依赖固定基础模型、人工设计的搜索空间、评估器或沙箱？

先读 **GEPA → Gödel Agent → Darwin Gödel Machine → AIDE²**，逐步比较提示词、逻辑、程序代码和科研流程的修改范围。论文数字与结论均以作者报告为准，未在本库独立复现。完整字段与最近核验日期见[论文库](papers.md)。

## 与主指南及评估协议的连接（2026-10-05）

主指南将技能/记忆积累、提示词/程序优化和模型训练分开。DeepSeek-R1 已在论文库归入“规划与推理”的基础方法：R1-Zero 的纯 RL 与 R1 的冷启动、SFT、多阶段 RL 不能混称为“运行时 Agent 自我升级”。[原始修订版 §2–3](https://arxiv.org/html/2501.12948v2)支持这一训练阶段区分；前文其他 RSI 工作沿用原核验日期。

读完五个问题，再检查**可改组件与不可改评估器**的边界，保留每代版本、接受/拒绝的证据，以及全部尝试的资源开销。反馈预算内的提高、留出任务迁移与长期稳定提高是三个待分别验证的结果。上下文积累可能只是改变信息可见性（见 [MemGPT](https://arxiv.org/abs/2310.08560)），不能仅因下一轮读到更多经验就判定改进器本身产生递归收益。

## 执行器改进与改进器改进（2026-10-12）

读完 DGM/AIDE² 后，用 [VERSE](https://arxiv.org/html/2610.02616v1)区分两层：执行器版本改变后重新解题；改进器版本改变后重新提出和验证修改。其诊断、补丁验证、回放和扰动检查有固定接口；自改程序还需安全检查与 smoke test。主实验使用四个重实现宿主、六轮演化，封存 ID/OOD 测试剔除参考实现失败后分母为 108/107。测试的 avg@3 是同一演化产物的三次评估，不能写成三次独立演化；主表每项只有一次演化运行。探测预算单位相同不等于全部工具调用、token 或费用相同。代码入口为[作者仓库](https://github.com/wzekai/VERSE)，未运行；10 月 2 日首次提交，属于较早补收。

**经验路由也不是自动成立的 RSI。**[Component Routing](https://arxiv.org/abs/2610.01787)把同一经验拆成定位、程序步骤、状态事实和失败经验，再比较进入上下文或权重。它帮助说明修改对象与训练/推理阶段；这组对照本身没有证明改进器递归变强。三个模型、两个环境的收益与费用仍需分别看，且 AndroidWorld 上一个模型相对全部放上下文的差异区间包含零。先读记忆与 GUI 章节，再将其作为修改面辨析，保留 GEPA 的提示演化路线。

## 参数更新与反馈来源（2026-10-19）

前面的程序演化保留原路线；下面增加参数学习分支。**反馈来自环境、同一模型的评价角色还是独立报告者，必须分别记录。**“外部”可指独立于被修改程序的检查器，也可指循环外的评估模型，不能混用；循环内自评不天然独立，独立报告也不证明没有训练污染。

| 工作 | 修改对象、反馈与下一轮 | 阅读边界 |
| --- | --- | --- |
| [MASS](https://arxiv.org/abs/2610.12176) | 内层搜索工作流并用当前模型评价，外层对编排/子 Agent 轨迹做 LoRA SFT；更新后的共享模型再当执行器、优化器和评价器。 | 两轮参数更新不是运行时改写训练算法。外部成对报告不回传内环；六次判分是同一产物对的重复评判，不是六次独立任务执行。 |
| [Terminal-RSI](https://arxiv.org/abs/2610.22192) | 验证过的发现被重写、重新执行并过滤，再做 actor 监督训练；后续策略优化继承 critic，新策略进入下一轮。 | 训练与奖励流程由研究者设定；保留阶段上升不代表所有分支持续变强，Mean@3 只是推理重复。 |

读 MASS 时，先看自评排序、验证损失选 checkpoint 和循环外评价分别用在哪里；再检查训练后的共享模型怎样回到三个角色。它连接多 Agent 工作流与模型学习。[作者实现](https://github.com/SakanaAI/mass)提供研究入口；这是10月8日的较早补收，实验范围与条件见[论文库记录](papers.md#paper-2610.12176)。

Terminal-RSI 可用于区分过程奖励、严格完成与验证覆盖：先看轨迹如何通过验证进入训练，再看 actor/critic 如何进入下一轮。它补训练阶段的递归实例，与 GEPA 的提示演化和 VERSE 的固定权重改进器形成对照。本期补查 10 月 30 日的 [v3](https://arxiv.org/html/2610.22192v3)，不是本周新论文：相对v2有正文限定语、历史协议与LHTB聚合表述的删改；未见新增对应的独立训练或组件隔离对照，仍沿用已报告阶段结果。方法部署的作者表述与组件因果收益分别判断，详细版本证据放在[核验日志](https://github.com/Scodive/AI-Agent-Guide/blob/main/data/verification-notes.md)。实验范围与条件见[论文库记录](papers.md#paper-2610.22192)。

## 记忆状态变化与管理策略变化

[MCCL](https://arxiv.org/abs/2610.29357)把持续记忆拆成两个修改面：内层更新保存的事实、事件和程序，外层改变写入、检索、整理和修订这些内容的策略。固定策略根据不同状态选择不同操作，仍不等于策略自身被修改；离线训练后冻结的记忆控制器，也要与部署中的策略更新分开。

读者可以用三个例子定位：A-MEM 增加或链接一条经验，改的是记忆状态；GEPA 优化负责记忆管理的提示词，才可能改管理策略；若被接受的新策略继续参与生成和筛选下一代，还要另检查递归链和评价条件。第二、三个例子是编者对修改对象的说明，不是 MCCL 已完成的实验。

因此持续学习不以 RSI 为前提；反过来，修改过管理策略也不自动证明持续收益。MCCL 建议在匹配模型/预算的 stateful–reset 对照中测延迟与干扰后的留存、变化适应和跨任务迁移。其 IdeaBench 探针期间继续写入记忆，有限实证和合成缩放示意不能当作整个双层循环已获验证。保留 GEPA/DGM/VERSE 与 MASS/Terminal 的现有路线，在比较表旁先写清“这轮改内容、规则还是参数”。
