# RSI：Agent 的递归自我改进

*论文核对：2026-09-27。以下结论为作者报告，未独立复现。*

这里的 **RSI（recursive self-improvement）**限定为：系统提出对自身某个可复用组件的修改，以外部反馈筛选修改，并让被接受的新版本参与下一轮改进。关键要问的是**改了什么、谁给分、改进能否迁移、下一轮是否真的使用了改进后的系统**。这比“Agent 反思了一次”或“模型训练后分数更高”更具体。

## 改进对象不同，证据也不同

| 层次 | 代表工作 | 改进对象与循环 | 不能据此推出什么 |
| --- | --- | --- | --- |
| 提示词/模块说明 | [GEPA](https://arxiv.org/abs/2507.19457) | 读取轨迹与工具结果，生成自然语言反思，更新提示词，并从候选的 Pareto 前沿保留互补经验。 | 改进提示词不等于修改模型权重，也不自动证明 Agent 能自主设计下一代模型。 |
| Agent 逻辑 | [Gödel Agent](https://arxiv.org/abs/2410.04444) | 用高层目标引导 Agent 改写自身逻辑和行为，再在推理与复杂任务上评估。 | 有限任务上的迭代收益不代表开放环境中无限改进。 |
| Agent 程序代码 | [Darwin Gödel Machine](https://arxiv.org/abs/2505.22954) | 从已有 Agent 档案采样，修改自身代码，用 Coding 基准筛选新版本；被保留版本可继续产生后代。 | 改进的是以固定基础模型为核心的 Agent 程序，不是基础模型自行重训。 |
| 科研 Agent 自身 | [Recursive self-improvement of AI research agents（AIDE²）](https://arxiv.org/abs/2609.26457) | 研究 Agent 改写自身代码，用 AI 研发任务筛选，并检查留出任务上的转移。 | 论文报告的是特定 Agent、任务和一次八天运行；不能概括为通用自主 AI 研发已解决。 |

**相邻但不同：**[AlphaEvolve](https://arxiv.org/abs/2506.13131)用代码生成、自动评估与演化搜索改进**目标算法**，包括部分 AI 计算基础设施；这证明闭环算法发现有用，但算法改进不必然是 Agent 改写自己的改进器。[Voyager](https://arxiv.org/abs/2305.16291)积累技能库，适合作为持续学习的前置阅读。[DeepSeek-R1](https://arxiv.org/abs/2501.12948)讨论模型强化学习，不能直接当成 Agent 运行时 RSI 的证据。

## 读 RSI 论文时检查五个问题

1. **修改面**：提示词、工具、记忆、搜索策略、评估器、完整 Agent 代码，还是模型参数？
2. **反馈面**：训练任务与保留任务是否隔离？运行失败、超时和验证错误怎样处理？
3. **递归性**：新版本是否真的成为下一轮的修改者，还是仅对同一固定系统做多次搜索？
4. **收益**：报告的是任务成功率、成本/时延、迁移能力，还是只看优化器反复使用的同一评分？
5. **边界**：改进是否依赖固定基础模型、人工设计的搜索空间、评估器或沙箱？

先读 **GEPA → Gödel Agent → Darwin Gödel Machine → AIDE²**，逐步比较提示词、逻辑、程序代码和科研流程的修改范围。论文数字与结论均以作者报告为准，未在本库独立复现。完整字段与最近核验日期见[论文库](papers.md)。
